# 订单模块的客服回复链路

订单模块独立管理话术库、提示词、生成器、规则校验和运行记录。商品推荐项目没有被本次改动修改；最终可以共用客服界面，各模块仍返回自己已经核验的客服消息。

## 本轮回复如何产生

1. 原订单查询和快递 HTTP 接口提供本轮事实。
2. `KnowledgeRetriever` 根据订单场景筛选数据库话术，再按用户关键词评分，取最多两条。
3. `OrderReplyGenerator` 将订单号、订单/包裹状态、预计时间和人工处理边界构造成事实占位符。手机号与用户编号不进入回复模型输入。
4. DeepSeek 根据用户问题、最近对话、检索话术和事实占位符生成自然表达。
5. 规则校验确保事实占位符全部且只引用一次，不允许自行填号码、金额、状态、时间或声称执行动作。
6. 独立模型调用检查语义、事实连接和服务边界。未通过时最多重写一次。
7. 无模型、超时、接口失败或生成不合格时，使用实际检索到的话术兜底，保留已确认的订单与物流结果。记录明确标注兜底，不冒充模型生成成功。

当前检索是**场景过滤与关键词评分**，没有声称使用向量数据库或语义向量召回。`knowledge.json` 含20条补建演示话术；原Coze话术知识库正文目前不在项目中，来源标记为 `reconstructed_demo`，不能宣称已经复用原知识库。

## 独立优化的位置

| 内容 | 文件 |
|---|---|
| 场景话术、引导和示例 | `order_reply/knowledge.json` |
| 检索规则及关键词评分 | `order_reply/knowledge.py` |
| 客服话术生成提示词 | `order_reply/prompts/compose.md` |
| 独立质检提示词 | `order_reply/prompts/review.md` |
| 事实构造、生成重试与兜底 | `order_reply/generator.py` |
| 回复模型调用 | `order_reply/model.py` |
| 检索/生成运行记录 | SQLite `order_reply_runs` |
| 自动检查 | `tests/test_order_reply.py` |

编辑生成或质检提示词后，后续模型调用会重新读取文件。改动Python实现需要重启订单服务。修改 `knowledge.json` 后，在项目根目录显式同步：

```powershell
python -m order_reply.knowledge --sync
```

同步会覆盖同编号话术条目的内容；不会删除未包含的其他条目，不改写订单、会话或工单。正常服务启动只补齐不存在的条目，保留数据库中已有的人工编辑。修改话术时应同时更新版本；要暂时禁用某条可将数据库该条的 `enabled` 设为0。

## 调试与数据库

数据库自动升级到版本6，新增 `order_reply_knowledge` 和 `order_reply_runs`，保留已有订单、物流、会话与人工记录。升级前已在 `artifacts/reply-backups/` 保存源码边界及SQLite备份。

每次聊天响应包含 `reply_status`：场景、检索条目编号/版本/来源/评分、匹配关键词、生成方式、尝试次数、质检是否通过、兜底原因和耗时。

页面右侧折叠面板“订单模块：话术检索与回复生成”显示这些记录，普通客服消息只展示可读回复。`GET /api/reply/runs` 返回当前演示账号最近30条记录，需要登录，不能查看另一账号记录，不输出密钥或请求认证头。

事实仍由订单和本轮快递查询确定。话术库不是订单事实库，不能根据话术示例推断已发货、已签收、退款成功或已创建工单。物流接口失败时不沿用旧轨迹；多包裹必须保留分别查询结果；有来源的预计时间需要保留且不能说成保证时间。

## 验证

```powershell
python -m unittest discover -s tests -v
```

自动检查使用脚本模型回复，不消耗模型额度。真实模型验证工具：

```powershell
python artifacts/reply_live_verify.py
```

该工具需要订单服务正在运行及本机DeepSeek配置，会实际调用模型并消耗额度。结果记录在 `artifacts/reply-live-verification.json`。浏览器证据及总体验证见 `artifacts/reply-verification.json`。

后续统一界面接入时，由订单适配器调用该生成器并返回 `reply` 与模块调试记录；界面不能把所有模块回复重新套进一套通用模板。本轮没有把订单语气规则写入商品推荐提示词，也没有接管推荐的理由生成/话术生成链路。
