# 零食电商智能客服 Demo

这是独立运行的客服项目。Coze 导出仅作为最初业务参考，不作为运行依赖。

## 当前进度

**订单模块已接入同一客服界面；整体验收仍未全部通过。** 本轮新增订单自动分流、原订单话术链路、模拟快递HTTP查询、账号隔离和跨模块状态保留，并将临期排除设为店铺默认规则。结果见 [订单整合验收](docs/10-订单模块整合与临期规则验收.md)。

之前推荐版本的98场景、250轮服务验收和34轮故障对照，按逐项自动断言55项通过、43项未通过。完整历史结果见 [第五步验收记录](docs/09-第五步业务验收.md)，该记录不是当前集成版本的全量复测。不提供自然语言整体准确率。

已补齐原工作流中的“推荐理由 → 客服话术 → 最终质检”，不再直接把方案与金额列表当作线上回答。新效果、原节点对应关系和执行证据见 `docs/08-推荐理由与客服话术优化.md`。刷新页面并开始新咨询即可体验；历史消息保持原样。

实施顺序：

1. 会话、模块接口与统一消息格式（已完成）。
2. 演示数据、业务规则、复杂边界与 AI 易错点验收矩阵（已完成）。
3. 商品推荐核心：需求补丁、检索、过滤、组合、优惠计算、排序、事实校验与会话提交（代码及离线验证已完成）。
4. 客服对话界面：文本与消息内推荐卡片（已完成；真实模型关键流程及浏览器异常检查已执行）。
5. 完整业务验收：98场景已逐项执行，38个高风险场景各重复5次；已修复确定性缺陷，剩余未通过项见第五步记录。

订单实现通过 `integration/` 从相邻 `../snack_customer_service` 接入，原源码与订单库由适配层只读使用。订单参数由规则解析，客服话术由原模块检索、DeepSeek生成及独立核验负责；模型失败明确使用知识话术兜底。参见 [接入说明](integration/README.md)。

## 打开客服界面

在项目目录执行：

```powershell
python -m runtime.web --port 8787
```

然后打开 **http://127.0.0.1:8787/**。也可运行 `./start_demo.ps1`，它会在后台启动服务并打开浏览器。服务已启动时复用当前服务；修改 `.env` 后需要重启服务。

需求或订单问题直接输入聊天框，按 Enter 发送，Shift + Enter 换行。推荐卡片在客服消息内部展示，可选择具体商品修改数量或预算。订单回复保留在同一对话中，多个候选订单提供选择按钮。切换演示身份会开始新会话：新客对应订单账号A，老客对应账号B，其他身份没有绑定订单。物流来自本机模拟快递HTTP接口；售后与人工尚未接入。

可选“普通新客 · 订单账号 A”，输入“查询订单 SN-DEMO-0001 是否发货”“查询订单 SN-DEMO-0002 物流到哪了”或“查我之前买的薯片订单”。“普通老客 · 订单账号 B”可以查询 `SN-DEMO-0010`，不能读取账号A订单。

也可以直接输入下单手机号：账号A使用 `13800000001`，匹配9笔订单，先展示最近5笔供选择；账号B使用 `13800000002`，匹配1笔直接查看详情。手机号作为独立订单数据库的查询条件，不会改变当前账号。聊天框、首页“用手机号找订单”和演示说明均已提供入口。手机号链路与边界核验见 [手机号查询验收](docs/12-手机号订单查询验收.md)。

主推、备选、混搭、凑单与赠品默认排除距离到期日期不超过30天、过期或到期日期未知的商品。用户未提保质期或愿意接受临期也不会放宽。P024仅保留作反例数据。

可试：`办公室吃，必须独立小包，不辣，不要坚果，不要临期，最好低糖，买三件，含运费最多60元`，随后发送 `预算改成含运费40元，其他条件保留`。

商品及优惠为本地虚构资料，优惠时间固定为 `2026-10-07T12:00:00+08:00`。模型负责理解需求、解释推荐理由和组织客服话术；计价、库存、优惠资格和推荐卡片由后端事实库核验。密钥只在后端读取，不放进网页。完整功能与核验范围见 `docs/07-客服界面与第四步核验.md` 和 `docs/08-推荐理由与客服话术优化.md`。

## 运行本阶段检查

在本目录运行：

```powershell
python -m unittest discover -s tests -v
```

若环境未安装依赖，使用 `python -m pip install -r requirements.txt`。离线检查无须启动网页或提供模型密钥。

金额统一使用整数“分”，币种为人民币。展示时换算为元并保留两位小数。

第 2 步已固定有效期为开始包含/结束不包含、活动后用券、范围内门槛、整数半入取整、最大余数分摊、赠品单列及优惠后包邮门槛。完整规则以业务规则文档为准。

单独核对第 2 步资产：

```powershell
python tools/check_stage2_assets.py
```

67项是第二步历史检查数量，147项是第三步历史数量。最新代码检查为212项，通过；53个独立计价基准通过。98业务场景的最新结果以 `acceptance/stage5_execution.json` 为准，执行完毕不代表整体验收通过。

第五步复核已保存证据：`python tools/report_business.py`。真实服务验收：`python tools/accept_business.py --repeat required`，会使用本地DeepSeek接口额度。儿童年龄缺失、未知成分和非法输入等确定性保护可能在模型调用前完成；250轮服务执行不是250次HTTP模型请求。旧版与重跑证据保留，不从历史尝试中挑成功结果冒充当前稳定性。

第四步重新运行离线检查并汇总已保存的浏览器证据（不会主动调用模型）：

```powershell
python tools/verify_stage4.py
```

浏览器证据由 `tools/browser_verify.mjs` 在独立测试 Chrome 中实际运行生成；该工具需要本地测试浏览器的调试端口 9222。`live` 和 `faults` 模式含真实模型调用，会消耗接口额度。普通使用无须开启调试浏览器。

## 第三步运行入口

重新核验并保存执行记录：

```powershell
python tools/verify_stage3.py
```

明确的结构化离线输入，不调用模型：

```powershell
python -m runtime.cli --structured-input examples/need-office.json
python tools/export_offline_example.py
```

用户已选择 DeepSeek。按 `.env.example` 在项目根目录创建 `.env`，本地填写密钥；不要将密钥发到聊天或放入网页。配置后可运行真实模型入口：

```powershell
python -m runtime.cli --check-config
python -m runtime.cli --message "办公室吃，必须独立包装，不辣，最好低糖，含运费60元以内"
```

第一条只报告配置状态，不发送请求、不显示密钥。第二条是真实调用，会消耗接口额度；没有配置则明确报错。默认模型名称依据 2026-10-07 官方文档，可通过环境变量修改。

后续轮次使用前次返回的会话编号和版本：

```powershell
python -m runtime.cli --message "预算改成含运费40元" --conversation-id <会话编号> --revision 1
```

CLI 默认使用演示固定时间，可通过 `--now` 指定带时区时间。`--demo-user U_NEW` 等选项由本地演示入口提供可信身份，不从聊天文本读取会员/新客资格。会话存入被忽略的 `.local/sessions.sqlite3`。`--trace` 显示内部诊断，默认客服网页不会展示这些实现细节。
