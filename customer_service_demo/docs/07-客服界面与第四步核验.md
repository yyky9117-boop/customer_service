# 第 4 步：客服对话界面与关键链路核验

> 本文保留第四步初版的检查数量与执行记录。推荐表达已进一步补齐模型理由、客服话术和质检，最新结果见《08-推荐理由与客服话术优化》。

已完成本地客服网页，并使用用户配置的 DeepSeek 真实接口跑通“输入需求 → 需求补丁 → 商品及优惠查询 → 计价与排序 → 客服文本和消息内推荐卡片”。这是现有 Python 推荐项目的界面扩展，不依赖 Coze。商品、活动、券及演示身份仍是虚构的本地资料；未部署向量数据库。

## 使用方法

1. 在 `customer_service_demo` 目录执行 `python -m runtime.web --port 8787`，或运行 `start_demo.ps1` 后台启动并打开浏览器。
2. 打开 `http://127.0.0.1:8787/`，在聊天框输入需求。Enter 发送，Shift + Enter 换行。
3. 商品卡片内的箭头可选中具体商品，卡片底部可选中整个方案。输入框上方显示当前引用，可随时取消。
4. 继续说“预算改成含运费40元，其他条件保留”，或选中商品后说“这款改成两件”，会继承已有需求并重新核算。
5. 左侧可以恢复历史咨询；“开始新的咨询”清空当前上下文。切换演示身份也开始新会话，已有会话的身份保持固定。

不需要将密钥粘贴到网页。服务启动时从项目 `.env` 读取本地配置；修改配置后重启。页面顶部初始“已配置”仅表示存在配置，成功处理后才显示“推荐模块已接入”。当前真实核验使用 `deepseek-flash`，实际运行模型名称由本地配置决定。

本项目使用 8787 端口，避免占用现有订单演示的 8765。服务仅监听本机；启动入口检查已运行的演示服务。Windows 监听采用独占绑定，端口被占用会明确失败。

## 页面与交互

- 桌面：历史会话导航、客服消息区、底部输入框。推荐全部显示在客服消息内部，没有单独的右侧推荐栏。
- 手机：会话导航折叠；商品卡片纵向排列。已在 390 × 844 和 1440 × 1000 两种视口检查横向溢出并保存截图。
- 每个方案显示购买商品与数量、单价、商品应付、运费、整单应付、推荐理由、条件备注及可展开的优惠明细。运费或资格未知时显示待确认。
- 起始示例和追问快捷回复只填入可编辑草稿，由用户发送。
- 等待中显示进度，可停止等待。停止浏览器等待不撤销服务端处理，因此显示“结果待确认”，保留同一请求编号供安全重试。
- 失败保留原输入，不生成成功卡片。重试使用同一请求编号，已保存的成功回复不会重复写入。刷新时查询已完成请求缓存，并保留用户另写但未发送的下一条草稿。
- 会话与请求缓存按浏览器身份隔离。浏览器只拿到展示所需事实，拿不到密钥、内部需求状态或诊断信息。用户与模型文本按纯文本显示。

商品缩略图为通用零食包装 SVG 示意，并非真实商品照片。页面品牌“拾味”仅用于此演示。优惠核验时间固定为 **2026-10-07 12:00:00（上海时间）**，页面信息入口注明，避免虚构资料随真实日期漂移。

## 本步已执行的验证

证据：`acceptance/stage4_execution.json`。离线测试当前 **165 项全部通过**，包括新增的 15 项 HTTP 检查和 3 项商品引用回归检查；生产计价另含 **53 个既定数值基准**，这些是测试内的基准子检查，不应与测试方法数相加当作业务场景数。

浏览器的三个阶段共保存 **25 条检查记录**，其中 5 条为截图保存记录、20 条为行为或错误检查。结果均通过；控制台未出现脚本或内容安全策略错误。

真实 DeepSeek 从浏览器发起并完成的关键流程：

| 输入或操作 | 实际核对结果 |
| --- | --- |
| 办公室、独立小包、不辣、不要坚果和临期、最好低糖、三件、含运费不超过60元 | 输出首选及备选卡片；首选原味燕麦小饼干三件，商品38.70元、运费6.00元、整单44.70元 |
| 继续修改含运费预算为40元，其他条件保留 | 原有数量及要求保留；展示方案整单金额分别39.70、34.70、36.70元，均不超预算 |
| 选择原味燕麦小饼干，改成两件，保留40元含运费预算 | 只返回所选商品，两件商品25.80元、运费6.00元、整单31.80元 |
| 刷新已完成的对话 | 恢复原会话、版本和已保存的卡片 |
| 泛泛要求“推荐点零食” | 必要追问，不提前生成商品卡片 |
| 只要无糖礼盒且必须礼盒包装，含运费最多10元 | 无匹配，不编造符合要求的商品或低价方案 |
| 注入一次失败后重试真实请求 | 沿用原请求编号，最终真实模型完成推荐，页面只保留一条用户消息 |

异常与竞态由测试浏览器注入，属于故障处理验证，不能宣称真实供应商发生了故障：

- 注入模型超时：显示失败、保留输入、无卡片。
- 模拟服务器已保存成功但浏览器丢失响应：刷新从请求缓存恢复，避免重复展示用户消息。
- 缓存恢复期间有不同的下一条草稿：保留下一条草稿。
- 加载历史时切到新咨询：迟到的历史响应不覆盖新咨询，发送按钮正常可用。
- 注入 HTML 文本：按文字显示，不执行其中脚本。
- 注入一直等待的请求并停止：显示结果待确认，不伪装为已取消服务端操作。
- 切换演示身份：开始新会话。

本步发现并修复了两类真实问题：选中商品后修改数量仍推荐其他 SKU；模型偶尔将完整糖标签 `sugar:sugar_free` 错写为 `sugar_free`。前者由后端根据已核实引用落实商品筛选条件，并明确保留、替换、比较备选三种动作；后者补充完整取值提示和校验修复反馈，非法值仍拒绝进入推荐。
